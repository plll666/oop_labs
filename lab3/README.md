# Отчёт по лабораторной работе №3

**Тема:** множество объектов с динамическим массивом и перегрузкой операторов.

**Вариант:** 11 — Student.

## Цель работы

Реализовать множество объектов с ручным управлением памятью, применить правило
пяти и перегрузить операторы для работы с множествами.

## Задание

Создать класс `Student`, который хранит имя в массиве `char*` и номер `id`.
Студенты сравниваются по `id`. Реализовать класс `StudentSet` на динамическом
массиве без повторяющихся элементов. Для обоих классов выполнить правило пяти.
Множество должно поддерживать добавление, удаление, поиск, объединение,
пересечение, разность, сравнение и вывод в поток.

## Ход работы

Класс `Student` хранит поля `name_` и `id_`. Конструктор выделяет память для
имени с учётом завершающего нулевого символа. Копирование создаёт отдельный
массив, а перемещение передаёт указатель новому объекту. После перемещения
исходный студент имеет пустое имя и `id`, равный 0.

В `StudentSet` хранятся указатель `data_`, размер `size_` и ёмкость `capacity_`.
Первое добавление выделяет место для одного студента. При заполнении массива
ёмкость удваивается, а студенты перемещаются в новый массив.

Поиск выполняется линейно по `id`. Новый студент добавляется в конец.
Если такой `id` уже есть, добавление возвращает `false`, имя не меняется.
При удалении оставшиеся элементы сдвигаются, поэтому порядок сохраняется.

Для копирующего присваивания используется copy-and-swap. Перемещающее
присваивание освобождает старый массив и забирает чужой. Самоприсваивание
и самоперемещение обрабатываются в обоих классах. Деструкторы освобождают
массивы через `delete[]`.

Операторы `+=` и `-=` добавляют и удаляют одного студента. `contains`
и `operator()` проверяют наличие студента по `id`.

Объединение `|` сначала копирует левое множество, затем добавляет недостающих
студентов из правого. Пересечение `&` оставляет общие элементы, а разность `-`
оставляет элементы левого множества, которых нет в правом. Исходные множества
не меняются. При совпадении `id` в результате сохраняется имя из левого множества.

Равенство множеств проверяется по размеру и наличию одинаковых `id`.
Порядок добавления и имена на результат сравнения не влияют.
Вывод сохраняет порядок хранения: `{ (1, Ivan), (2, Anna) }`.

## Проверка работы

Использованы C++20, CMake 3.20+ и Google Test. Окружение `.devcontainer`
настроено по образцу предыдущих лабораторных. Папка `lab3` открывается
в VS Code через Reopen in Container, после чего проект собирается автоматически.
Google Test загружается через CMake при первой сборке.

Написано 22 теста. Проверены копирование и перемещение обоих классов,
самоприсваивание, дубликаты, удаление, операции над множествами и вывод.
В stress-тесте добавляются 1000 студентов, затем проверяется наличие каждого
и отказ при повторном добавлении.

Devcontainer успешно запущен, автоматическая сборка и демонстрационная
программа работают. Все 22 теста прошли внутри контейнера в обычной сборке
и с AddressSanitizer и UndefinedBehaviorSanitizer. Проверка утечек включена
(`ASAN_OPTIONS=detect_leaks=1`), ошибок не обнаружено. Отдельно проверены
искусственные отказы выделения памяти при копировании и добавлении:
старое множество сохраняется, выделенные временные массивы освобождаются.

Результат запуска демонстрационной программы:

```text
A = { (1, Ivan), (2, Anna) }
B = { (2, Anna), (3, Oleg) }
A | B = { (1, Ivan), (2, Anna), (3, Oleg) }
A & B = { (2, Anna) }
A - B = { (1, Ivan) }
Copy after remove = { (2, Anna) }
A after copying = { (1, Ivan), (2, Anna) }
Moved = { (2, Anna) }
Source after move = {}
```

## Вывод

Реализованы классы `Student` и `StudentSet` с ручным управлением памятью.
Правило пяти выполнено для элемента и множества. Перегружены операторы
для основных операций над множествами. Работа программы проверена тестами.
